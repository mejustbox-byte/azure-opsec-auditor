# Инструкции для последующих циклов разработки

- Вся пользовательская документация, справка, описания правил/схем, шаблоны и release notes — на русском. Команды, пути, ключи JSON, идентификаторы и код не переводить. Полный стандартный английский LICENSE MIT сохраняется; LICENSE.ru.md — справочный перевод.
- README содержит полный индекс основных корневых документов, сохранённых docs и security/license материалов. Новые документы добавлять в индекс и проверять локальные ссылки; не заменять содержательность объёмом текста.
- Использовать существующий изолированный checkout; Git worktree — только по явному запросу. Сохранять чужие изменения. Установка и проверки должны работать из checkout без сохранённого venv и onboarding-каталога.
- Разработка аудитора только на синтетических данных. Не создавать платные ресурсы, не выполнять реальную Azure/Entra auth/tenant проверку без отдельного разрешения, не включать exports/credentials/UPN/реальные отчёты в публичный git или артефакты.
- `pass` относится к конкретной записи и узкому правилу. Неполные/недоступные источники дают unknown/not_run. Синтетические, локальные, удалённые CI и реальные лабораторные проверки различать; невыполненные gates явно помечать НЕ ВЫПОЛНЕНО.
- Запускать актуальные тесты, сигнатурный/ссылочный скан, сборку и проверку установленного wheel/sdist вне исходников. Проверять MIT metadata и оба license files. Не отключать TLS, hashes, assertions и не подменять проверки фиктивным успехом.
- PR/merge/release выполнять только в разрешённой пользователем задаче. Перед слиянием проверять фактический HEAD и зелёный CI. Перед выпуском сверять package version/tag/commit; теги и существующие assets не передвигать и не перезаписывать. Старые выпуски не удалять.
- При upload 401 использовать проверенный Actions release workflow и штатный GITHUB_TOKEN с contents:write только у release job; новые credentials не добавлять, значения не раскрывать, auth не обходить. После выпуска проверять public prerelease, точный tag, полный inventory и скачанные SHA256.
- Обновлять русские install_script/start_skill и точный commit среды через draft. Сохранение draft не означает публикацию или успешное восстановление; новый cloud task проверять отдельно и сообщать фактические результаты/блокеры.
