# Локальная лаборатория Azure / Entra

## Проверенная offline лаборатория

Разработка использует только синтетические fixtures. На Linux с Python 3.12 выполнить [INSTALL.md](INSTALL.md), затем:

```bash
python -m azure_opsec_auditor fixtures/good.json --as-of 2026-10-09T12:00:00Z
python -m azure_opsec_auditor fixtures/bad.json --as-of 2026-10-09T12:00:00Z --format markdown
python -m azure_opsec_auditor fixtures/mixed.json --as-of 2026-10-09T12:00:00Z
```

Коды завершения соответственно 0, 1, 2. Для mixed ожидаются по три результата каждого состояния. Дата фиксирована для воспроизведения; проверка свежести реального снимка требует текущего времени. Windows-команды документированы, но запуск на Windows **НЕ ВЫПОЛНЕНО**. FIFO regression test относится к POSIX и на Windows пропускается.

## Отдельный реальный tenant: пока НЕ ВЫПОЛНЕНО

Продукт не содержит live collector, Azure SDK, auth или автоматического экспорта. Для будущей валидации оператору нужен отдельный разрешённый тестовый Azure/Entra tenant, тестовая подписка и, где требуется, лицензии PIM/Conditional Access. Создание оплачиваемых ресурсов и использование реальных credentials в этом цикле не разрешены и не выполнены. Нельзя считать записи JSON доказательством фактического effective access: поля являются утверждениями источника.

До лабораторного запуска согласовать владельца, область, минимальные read-only Graph/ARM роли, доступность лицензий, бюджет и остановку/очистку. Не выдавать глобальные write/admin права аудиторскому процессу; любые изменения тестовых политик выполняет отдельный оператор. Conditional Access исследовать с аварийной учётной записью и report-only/контролируемыми политиками, чтобы избежать блокировки. Не менять production tenant.

Матрица приёмки:

| Область | Реальный контроль и доказательство | Текущий gate |
|---|---|---|
| RBAC/PIM | Сравнить scope, permanent/eligible assignments и approval/MFA/duration с независимым чтением ARM/Graph; проверить вложенные группы | НЕ ВЫПОЛНЕНО |
| Conditional Access/MFA | Учесть exclusions, report-only, authentication strengths и effective policy; ограничить выводы MVP | НЕ ВЫПОЛНЕНО |
| Service principals/OAuth | Владельцы, истечение, application grants, consent и delegated grants отдельно | НЕ ВЫПОЛНЕНО |
| Managed identities/OIDC | Реальные assignments, issuer/subject/audience и effective federation; не доверять одному broad-флагу | НЕ ВЫПОЛНЕНО |
| Key Vault/Storage/сети | ACL, firewall/private endpoint, anonymous reachability и эффективные NSG/маршруты без опасного сканирования | НЕ ВЫПОЛНЕНО |
| Журналирование | Проверить доставку событий и retention на принимающей стороне, не только destination flag | НЕ ВЫПОЛНЕНО |
| Восстановление | Контролируемое восстановление тестового объекта с измерением RPO/RTO; backup flag недостаточен | НЕ ВЫПОЛНЕНО |

Для каждого gate зафиксировать дату, API/version, scope, права, pagination/ошибки, независимый ожидаемый результат и ограничения. При недоступном источнике использовать `unknown` или `not_run`, не пустой `complete` раздел. Сопоставлять поля строго по [CORE-CONTRACT.md](CORE-CONTRACT.md) и [матрице](docs/04-check-matrix.md); не заполнять недоступные булевы поля догадками.

## Приватность и завершение

Снимок и отчёты держать в отдельном приватном каталоге, исключённом из git; идентификаторы заменять согласованными псевдонимами. Псевдонимизация не гарантирует анонимность конфигурации. Политика хранения — [EVIDENCE.md](EVIDENCE.md). В публичный PR публиковать только синтетическую регрессию и обезличенное описание результата, без exports, токенов, UPN и имён ресурсов.

Оператор отдельно проверяет удаление временных ресурсов/политик и восстановление исходного лабораторного состояния. Read-only CLI не выполняет очистку и не может доказать её. Успешный реальный lab нужен для расширения заявлений о платформенной валидации; текущий выпуск остаётся prerelease.
