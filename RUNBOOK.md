# Эксплуатация локального аудитора

MVP запускается одной командой, без сервиса, базы, фонового scheduler, cloud login или сетевого сканирования. Установка: [INSTALL.md](INSTALL.md); контракт: [CORE-CONTRACT.md](CORE-CONTRACT.md). Успех процесса не подтверждает безопасность tenant.

## Обычный запуск

```sh
.venv/bin/azure-opsec-auditor --version
.venv/bin/azure-opsec-auditor fixtures/good.json --as-of 2026-10-09T12:00:00Z
.venv/bin/azure-opsec-auditor fixtures/mixed.json --as-of 2026-10-09T12:00:00Z --format markdown
```

Первый fixture даёт 0; mixed даёт 2 и отчёт с 3 pass/3 fail/3 unknown/3 not_run. Это синтетический контроль, не real tenant. Для текущего операторского снимка не подменяйте as-of историческим временем ради кода 0. Сохраняйте ожидаемые ограничения из каждого finding.

## Приватные отчёты

На POSIX оператор заранее проверяет владельца/права каталога, затем:

```sh
umask 077
mkdir -p -m 700 local-data
.venv/bin/azure-opsec-auditor local-data/snapshot.json --format json > local-data/report.json
```

snapshot.json создаёт отдельно разрешённая процедура нормализации; такого файла продукт не поставляет и CLI не собирает его из Azure. Код 1/2 не мешает stdout-отчёту при валидном снимке, но означает риск/неполноту. При ошибке ввода перенаправленный файл может быть пустым; не считайте его отчётом. CLI не проверяет ACL выходного файла, не шифрует и не удаляет копии — см. [EVIDENCE.md](EVIDENCE.md).

## Ошибки и восстановление процесса

| Симптом | Действие |
|---|---|
| код 2, ошибка ввода | сверить UTF-8, regular file, размер, schema/UTC/enum; не публиковать raw payload |
| unknown | устранить отсутствие полей/источника, partial/empty или старый collected_at; не выдумывать данные |
| not_run | раздел не собирался; это не pass и не неприменимость |
| код 1 | просмотреть evidence/limitations/remediation; любые реальные исправления отдельно согласуются |
| неожиданное зависание stdout/диска | остановить свой CLI, проверить storage/consumer; FIFO не допускается, медленный regular disk всё ещё возможен |
| несовпадение SHA256/версии | не использовать файл, снова проверить официальный release/tag и источник manifest |

У CLI нет постоянного состояния: после аварии повторите тот же regular snapshot с фиксированным as-of для детерминированного результата. Никакие ресурсы tenant не откатываются, потому что CLI их не изменяет. Ошибки не закрывайте пропуском тестов или снижением assertions/TLS/hashes.

## Обновление и инциденты

Новый wheel устанавливайте в отдельный venv, после проверки hashes/версии и синтетических кодов. Для отката используйте сохранённый неизменный старый wheel в другом venv; не перезаписывайте tags/assets. Оператор сам пересматривает retention/copies; удаление пакета не удаляет evidence.

Если в git/отчёт/issue попало чувствительное содержимое, остановите публикацию, ограничьте доступ и сообщите владельцу приватно по [SECURITY.md](SECURITY.md). Настоящее восстановление backup и cleanup лаборатории — [LOCAL-PC.md](LOCAL-PC.md), сейчас НЕ ВЫПОЛНЕНЫ.
